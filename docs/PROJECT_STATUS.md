# Состояние проекта NarrativeAI 3.1

## Реализуется в ветке v3.1
- Один Supabase-проект владельца приложения; пользовательские профили, истории и настройки изолированы RLS.
- Персональные API-токены для повествователя и режиссёра: AES-256-GCM шифрование на сервере, без возврата ключей клиенту.
- Проверка соединения с выбранной моделью из настроек ИИ.
- Режиссёр вызывается условно: первый ход, примерно каждый шестой ход и эвристически определяемые рискованные события; для проверки получает последние шесть сообщений.
- Закреплённая навигация на ПК, отдельная прокручиваемая область чата, мобильный полноэкранный диалог с кнопкой возврата.
- Обработка токенов после подтверждения почты и redirect на `APP_URL`.

## Обязательная настройка перед эксплуатацией
- Миграция `20261120115509_add_encrypted_ai_api_keys.sql` уже применена и проверена в подключённом Supabase-проекте; для нового проекта применить её после базовой схемы.
- Установить стабильный секрет `APP_ENCRYPTION_KEY` (64 hex-символа) и сохранить резервную копию.
- Для публичного домена указать `APP_URL` и добавить его в Supabase Authentication → URL Configuration → Redirect URLs.
- Проверить регистрацию и подтверждение почты, сохранение/удаление токенов, проверку API, генерацию, мобильную версию и изоляцию двух аккаунтов.

## Ограничения
- Проверка режиссёром эвристическая и не обнаружит гарантированно каждое противоречие.
- Поддерживается OpenAI-совместимый API `/chat/completions`; другие форматы провайдеров потребуют отдельного адаптера.
- Локальные Ollama/LM Studio доступны только если сервер приложения может обратиться к их адресу. На публичном хостинге `localhost` означает сам сервер, а не телефон/ПК пользователя.
- Старые SQLite-данные автоматически не переносятся.

## Основные файлы
- `server.js` — Express API, Supabase и вызовы моделей.
- `public/` — интерфейс приложения.
- `supabase/migrations/` — схема БД и политики доступа.
- `deploy/` — Docker и инструкции запуска.
