# NarrativeAI 3.1

Веб-приложение интерактивных историй с ИИ-режиссёром и ИИ-повествователем.

## Стек
- Node.js + Express
- Один управляемый владельцем Supabase-проект: Auth, PostgreSQL, Storage.
- RLS изолирует профили, настройки и истории каждого пользователя.
- Внешние OpenAI-совместимые API с персональными ключами пользователей.
- AES-256-GCM для шифрования API-токенов перед сохранением в PostgreSQL.

## Запуск
1. Установите Node.js 20 или новее.
2. Скопируйте `.env.example` в `.env`.
3. Укажите `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` вашего Supabase-проекта.
4. Сгенерируйте `APP_ENCRYPTION_KEY`: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
5. Для локального запуска оставьте `APP_URL=http://localhost:3000`. На публичном сервере укажите полный HTTPS-адрес приложения без завершающего слеша.
6. Выполните `npm install`, затем `npm start` и откройте адрес приложения.

**Важно:** храните `APP_ENCRYPTION_KEY` в секрете и сделайте резервную копию. Он должен оставаться неизменным: без него ранее сохранённые API-токены нельзя расшифровать.

## Миграции Supabase
Примените SQL-файлы из `supabase/migrations/` по порядку. Для обновления v3.0 → v3.1 выполните `20261117104714_fix_avatar_storage_select_policy.sql` и `20261120115509_add_encrypted_ai_api_keys.sql`.

Пользователям приложения не нужно создавать собственные проекты Supabase: все аккаунты и данные находятся в одном проекте владельца приложения. Доступ к строкам ограничен RLS, а клиент не получает service-role/secret key.

## Подтверждение почты
Укажите `APP_URL` для публичного развёртывания. В Supabase Dashboard откройте Authentication → URL Configuration: задайте Site URL равным `APP_URL` и добавьте этот адрес в Redirect URLs.

После подтверждения письма пользователь вернётся в приложение, где клиент обработает токены сессии. Для локальной разработки используйте `http://localhost:3000`.

## Настройка ИИ
В разделе «Настройки ИИ» пользователь выбирает провайдера, модель и Base URL, вставляет свой API-токен и может проверить соединение. Токен шифруется на сервере и не возвращается в браузер. Пустое поле при сохранении не заменяет уже сохранённый токен; для удаления есть отдельный флажок.

Поддерживается OpenAI-совместимый endpoint `/chat/completions`. Старый `AI_API_KEY` в `.env` оставлен как необязательный серверный fallback, но для публичного сервиса рекомендуется персональный токен каждого пользователя.

## ИИ-режиссёр
Режиссёр не вызывается на каждом ходе. Он проверяет первый ход, затем примерно каждый шестой ход, а также сообщения с признаками потенциально важных изменений (время, перемещение, появление/исчезновение персонажей, смерть, ранения и т. п.). Для проверки получает последние шесть сообщений и факты истории. Это эвристический механизм: он экономит запросы, но не гарантирует обнаружение каждого противоречия.

## Интерфейс
- На компьютере боковая навигация остаётся закреплённой, прокручивается содержимое.
- Диалог занимает отдельную область; прокручивается только переписка.
- На телефоне открытый диалог становится отдельным экраном с кнопкой «Назад».
- Для публичного сайта укажите HTTPS-домен и настройте Supabase redirect URLs.

## Docker
Из корня проекта выполните `docker compose -f deploy/docker-compose.yml up --build -d`. Перед запуском заполните корневой `.env`. Остановка: `docker compose -f deploy/docker-compose.yml down`.
